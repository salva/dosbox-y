DOSBox-Y explores debugging and automation on top of DOSBox-X, bringing interactive tools, Lua scripting and programmatic control around a shared native core.

Follow the project on GitHub Development status
Under active development

The source integration and debugger work are in progress. The directions below are not a claim of completed features or general save-state compatibility.

This initial repository publishes the project site. Reviewed integrated source will follow separately; no stable release or downloads are available here yet.

Development directions

One machine. Consistent ways to inspect it.

Shared debugging

A common native foundation for interactive and programmatic front ends, with clear ownership of execution, stops, breakpoints and observations.

Lua & MCP

Reusable Lua scripting, interactive evaluation and MCP integration for tooling—without creating competing emulator controllers.

State persistence

Further work on saving and restoring supported machine state, with explicit scope, reproducible checks and honest limits.

Built on DOSBox-X

DOSBox-Y is being created with Saivage v3.

DOSBox-Y is an independent experimental fork, not an official DOSBox-X release. It builds on the work of the DOSBox and DOSBox-X contributors and aims to keep upstream improvements while developing its own debugging and automation work.

For the established upstream emulator and its documentation, visit dosbox-x.com.
