# Process-local checkpoints through the original save engine (R2)

`SaveState::capture` and `SaveState::install` are the sole component traversals
for both ZIP saves and process-local checkpoint images. Memory and archive
adapters own member streams and settlement; component owners retain their
original codecs. Integrity/membership checking precedes installation, but this
is **not whole-owner semantic prevalidation**: an owner can fail after earlier
owners have installed. Such failures are fatal, not catchable refusals/rollback.
R4 semantic validation/archive revision remains separate.

The live adapter accepts named, replaceable process-local images. It has neither
a single-slot policy nor a 16-restore policy. Each successful restore advances
the native state context and projected epoch, rebases host tasks, and remains
stopped until explicit continuation. Epoch representability and the 64 MiB
per-capture capacity remain actual limits. Images are not portable host stack
snapshots. Restoring binds to the same suspended EXEC invocation, PSP, program
and mount identity; the existing pre-return disposal fence remains mandatory.

The old fixed depth/real-mode/16 MiB/immutable-mount catalogue is not the safety
argument. Admission still requires the original engine's quiescent audited
ancestry, normal interpreter (no unrepresented translated native code), deliberate
same-owner stop, neutral input/tasks, settled instrumentation, and the exclusive
native state lease. Local directory drives and original LocalFile reopen are
admitted, not arbitrary native drive/file subclasses. Active guest directory
search snapshots are refused because they are not encoded. `dirSearch` is the
cache's scratch population cursor (including the cursor left by SetBaseDir);
guest FindFirst copies entries to `dirFindFirst`, whose lifetime is checked.
Changed host file content stays changed: R3's nondestructive reopen and
callback-free old-handle retirement are unchanged. This is not external file
content rollback or transactional host filesystem restoration.

Fresh live launch uses a root pre-interpreter LoopStop seam and the existing
native frontier hook; no competing execution loop or fabricated service entry
is introduced. Worker selection retains precedence. Native attachment and lease
admission still govern checkpoint operations.

## Reproduce

Use independently configured heavy-debug SDL2 agent builds, one with
`--enable-debug-lua` and one with `--disable-debug-lua`; both use
`--disable-opengl --disable-avcodec`. Set `DOSBOX_TEST_BINARY` to the exact binary
and `SAIVAGE_CARD_WORK_ROOT` to owned disposable evidence storage.

- `python3 tests/original-foundation/checkpoint-stream.py` tests real common
  engine/adapters extracted into a small fixture (not native admission).
- `python3 tests/machine-service/checkpoint-projection.py` tests the actual Lua
  projection, with mocked native authority; includes allocation failure after
  effects, lease release and retained restore truth.
- `python3 tests/original-foundation/checkpoint-runtime.py` launches a real
  production emulator on an owned display, enters a natural EXEC child, stops,
  captures two images around explicit guest execution, restores the first 19
  times with epoch assertions, restores/replaces the second, holds across host
  delay and explicitly continues. Root and missing-image refusals are checked.
- `tests/original-foundation/stopped-save.py` exercises original ZIP paths;
  `DOSBOX_TEST_FILE_STATE=1` adds R3 changed-file/cursor/search witnesses.
- `tests/machine-service/lua-production-runtime.py` and
  `tests/stopped-continuation/exclusive-runtime.py` cover worker and selected
  Interactive/Bridge ownership paths. For Interactive Lua invoke the module's
  `run(False, lua=True)` function; for the no-Lua diagnostic regression invoke
  `run(False, no_lua=True)` (the script's default main tests native paths only).

## Qualification boundary

The runtime fixture uses normal/fixed3000 CPU, SDL surface, dummy host audio,
no guest sound activity and a tiny real-mode COM on a local writable mount.
Those inputs are evidence, not a permanent profile restriction or proof of all
other devices. Protected mode, larger memory, nested EXEC checkpoint restores,
active sound/device activity, arbitrary native resources/frontends and composed
parity remain unqualified. Native admission mocks do not independently approve
those cases. The parent retains device/parity/R4 qualification and independent
assessment; exact source/build identities and run evidence belong in card status.
